# Hidden Worlds: product and technical spec (v1, web)

This is the source of truth for what to build. `docs/BUILD_PLAN.md` says in what order. `CLAUDE.md` says how to work.

Every requirement has an ID (for example `ENG-4`). `REPORT.md` must list every ID with PASS, FAIL or BLOCKED and the evidence.

"Hidden Worlds" is a working title. The name must live in one place (`src/config.ts`, `APP_NAME`) plus the web manifest, which is generated from it.

---

## 1. What we are building

A daily seek-and-find game for the mobile web. The player pans and zooms around one large illustrated world and taps the objects shown in a tray. Code places every sprite, so the game always knows where each object is and how much of it is visible.

v1 is a **static web app** (installable PWA). It has no server, no accounts, no real payments and no real ads. Its job is to be good enough to measure whether strangers come back on day 7.

### In scope (must-have)

- Deterministic puzzle engine ported from `prototype/`, restructured as described in section 3.
- Sprite packs as data: a built-in vector placeholder pack, and a PNG pack path proven by an exported sample pack.
- Three worlds, 12 hidden residents.
- Daily puzzle, 7-day archive, Explore mode with level ladders.
- Hints, misses, stars, streak, stats, residents collection, world unlocks.
- Share text, share image, challenge links.
- Onboarding, settings, relaxed mode, colour-blind mode, sound, haptics, About and privacy screens.
- Premium "notify me" screen that measures intent honestly.
- Adapters for analytics, ads, purchases, sync and waitlist, all no-op by default.
- PWA: installable, works offline after first load.
- Content tools: pack build, pack validate, world audit, content calendar.
- Tests and a single `npm run verify` command.

### Out of scope (do not build)

- Backend, accounts, cloud sync, global leaderboards.
- Real payments, real ad SDKs.
- Native wrappers (Capacitor, app stores). Do not block them: see `SHELL-9`.
- AI image generation calls. A scaffold is a stretch item only.
- Localisation beyond English. Keep all user-facing strings in one module so it can be added.

## 2. Stack and repo

- `STACK-1` Vite, React, TypeScript in `strict` mode. Use the current stable release of each at build time.
- `STACK-2` State: Zustand (or React context if you judge it simpler; log the decision). No other state library.
- `STACK-3` Styling: plain CSS with custom properties (CSS Modules allowed). No CSS framework, no UI kit.
- `STACK-4` World rendering: Canvas 2D. No game engine, no WebGL.
- `STACK-5` Tests: Vitest for unit tests, Playwright for end-to-end. `@napi-rs/canvas` as a dev dependency for tools and tests that draw in Node (the prototype tests already use it; run Node with `--expose-gc` and call `gc()` between large generations, or the process can run out of memory).
- `STACK-6` PWA via `vite-plugin-pwa` (or a hand-written service worker if the plugin fights you; log the decision).
- `STACK-7` Schema validation for pack manifests and saved data: Zod.
- `STACK-8` Lint and format: ESLint with the TypeScript plugin, Prettier.
- `STACK-9` Runtime dependencies stay minimal. Every runtime dependency beyond React, React DOM, Zustand and Zod needs one line in `DECISIONS.md` saying why.
- `STACK-10` Fonts are self-hosted (Bricolage Grotesque for display, Figtree for body, both SIL OFL), with `font-display: swap`. The default build makes **zero** third-party network requests.
- `STACK-11` Vite `base` is `./` and all asset URLs are relative, so the build works from any path and inside a native web view.

Before using a library API you are not certain of, read its current documentation. Do not rely on memory for version-specific details.

## 3. Engine

The prototype (`prototype/src/engine.js`) is the reference for behaviour and tuning. Read it first. Its algorithm is proven: 120 seeded puzzles pass its invariants at about 84 ms each. Port the algorithm; change the structure as below.

### 3.1 The one structural change: logic must not depend on a canvas

The prototype builds each sprite's mask by rasterising it on a canvas, then measures visibility from those masks. Canvas anti-aliasing differs between browsers, so two phones could generate two different puzzles from the same seed. A daily puzzle must be identical for everyone.

- `ENG-1` `src/engine/logic` is pure TypeScript. It imports nothing from the DOM, canvas or React. It runs unchanged in Node and in every browser.
- `ENG-2` Sprite masks are **precomputed at pack build time** and shipped with the pack as data (1 bit per pixel at half resolution). The logic layer never reads pixels from a canvas.
- `ENG-3` Mask transforms (scale, flip, rotation) happen in pure TypeScript with nearest-neighbour sampling. Rotation is quantised to a fixed table of angles whose sine and cosine are literal constants in the source. Scales are quantised to a fixed set of steps. Cache transformed masks.
- `ENG-4` The logic path uses only `+ - * /`, `Math.floor`, `Math.round`, `Math.min`, `Math.max`, `Math.abs`, `Math.imul` and bit operations. No `Math.sin`, `cos`, `pow`, `sqrt`, `exp` or `random` in logic (they are fine in rendering). Positions and sizes in the output are integers.
- `ENG-5` Random numbers come only from the seeded generator in the prototype (`xmur3` + `mulberry32`). Keep those two functions bit-for-bit.
- `ENG-6` `generate(input) → PuzzleSpec`, where `input = { seed: string, difficulty: 1..5, worldId, pack: PackLogicData }`. `PuzzleSpec` is plain JSON-serialisable data:
  - `engineVersion`, `packId`, `packVersion`, `seed`, `difficulty`, `worldId`, `W`, `H`, `horizon`
  - `sprites[]`: `uid`, `spriteId`, `role` (`target | decoy | clutter | occluder | sky | resident`), `color`, `x`, `y`, `size`, `rotStep`, `flip`, `z`, `front`
  - `order[]`: uids in draw order
  - `targets[]`: uids the player must find, each with `visibility` (0..1)
  - `resident`: uid or null, with `visibility`
  - `stats`: passes, moved, forced, counts by role
- `ENG-7` Hit testing is part of the logic layer: `buildIdMap(spec, pack) → Int32Array` at half resolution, `hitAt(idMap, x, y)`, `findNear(idMap, x, y, radius, wanted)`. Same behaviour as the prototype.

### 3.2 Behaviour to keep from the prototype

- `ENG-8` World size 3200 × 2000 logical pixels. ID map at half resolution.
- `ENG-9` Difficulty config exactly as the prototype (`u = (d − 1) / 4`): targets `5 + d`; decoys `d − 1`; clutter 150→440; occluders 24→42; clouds 7; minimum target visibility 0.92→0.50; tuck probability 0→0.7; size multiplier 1.2→0.86; allowed overlap 0.02→0.30; target overlap 0→0.16. Keep them in `config.ts`.
- `ENG-10` Each object target is unique by sprite type **and** colour. Decoys share a target's type in a different colour.
- `ENG-11` `placeTucked`: hard difficulties hide targets partly behind an occluder, accepting a spot when estimated visibility is between `minVis + 0.04` and `0.90`.
- `ENG-12` Repair loop: measure true visibility, move any target under the floor, up to 10 passes, then bring it to the front as a last resort. `stats.forced` counts those.
- `ENG-13` Draw order is y-sorted with sky sprites behind and `front` sprites last.

### 3.3 New behaviour

- `ENG-14` Worlds: `worldId` selects the background painter, palette, horizon, occluder set, small-sprite weights and resident set. Section 5.
- `ENG-15` One resident per puzzle, chosen by seeded weighted rarity from the world's residents. It follows the same visibility floor as targets. It is a bonus: not required to finish.
- `ENG-16` `ENGINE_VERSION` is a constant. Any change that alters output for an existing seed bumps it and updates the golden files in the same commit.

### 3.4 Engine acceptance

- `ENG-A1` Invariants hold for at least 300 puzzles spread over 5 difficulties and 3 worlds: every target and resident meets the visibility floor; every target owns at least 20 pixels in the ID map; `findNear` at a visible target's centre returns it; no target has a twin of the same type and colour; `stats.forced` is 0 in at least 95% of puzzles.
- `ENG-A2` Determinism: generating the same input twice gives deep-equal specs.
- `ENG-A3` Golden files: for 12 fixed inputs, a hash of the canonical JSON of the spec equals the stored value. The **same golden check runs in Node (Vitest) and inside Chromium, Firefox and WebKit (Playwright)** and all four agree.
- `ENG-A4` Mean target visibility falls as difficulty rises (difficulty 1 mean ≥ 0.95, difficulty 5 mean ≤ 0.88).
- `ENG-A5` Speed: `generate` + `buildIdMap` p95 ≤ 250 ms in Node on the build machine. Report the measured number.
- `ENG-A6` A lint rule or a unit test fails if anything under `src/engine/logic` imports from outside it (other than types) or references `document`, `window`, `CanvasRenderingContext2D`, or the banned `Math` functions.

## 4. Sprite packs

Full format in `docs/CONTENT_PACK.md`. Requirements:

- `PACK-1` A `SpritePack` has two halves: **logic data** (manifest + masks; all the engine needs) and **art** (how to draw each sprite). The renderer asks the pack to draw; the engine never does.
- `PACK-2` Built-in **vector pack**: port the prototype's sprites (33 small objects, 9 occluders, cloud, 8 colours) as painters. Its masks are generated by `npm run pack:build` in Node and committed, so the browser never computes them.
- `PACK-3` **PNG pack loader**: loads `public/packs/<id>/pack.json`, its masks and its images. Images load lazily and decode before first draw.
- `PACK-4` `npm run pack:export-sample` rasterises the vector pack to PNG files and writes a complete PNG pack to `public/packs/sample-png/`. The app runs on it with `?pack=sample-png`. This proves that swapping in commissioned art is a data change, not a code change.
- `PACK-5` `npm run pack:validate <dir>` checks a pack against the schema and the rules in `CONTENT_PACK.md`, prints every problem with the file and field, and exits non-zero on any error.
- `PACK-6` Add what the three worlds need beyond the prototype's sprites: at least 4 new occluders each for worlds 2 and 3, and 12 residents. Placeholder quality is fine; they must be distinct and readable at play size.
- `PACK-A1` Unit test: the vector pack and `sample-png` both pass the validator.
- `PACK-A2` E2E: a full play-through passes with `?pack=sample-png`.
- `PACK-A3` The validator rejects each of these in a test fixture: missing file, wrong dimensions, missing colour variant, empty mask, duplicate id, unknown world reference.

## 5. Worlds and residents

All values live in `config.ts` / the pack manifest and are meant to be tuned.

| World | id | Feel | Unlock (Explore) |
| --- | --- | --- | --- |
| Meadow | `meadow` | The prototype's green valley, cottages, trees | Open from the start |
| Harbour | `harbour` | Water horizon, boats, crates, nets, a lighthouse | 3 different residents found |
| Night Market | `market` | Dusk palette, stalls, lanterns, awnings, barrels | 6 different residents found |

- `WORLD-1` Each world has its own background painter, palette, occluder set and small-sprite weights, so the three are obviously different at a glance.
- `WORLD-2` 12 residents, 4 per world: 2 common (weight 30 each), 1 uncommon (weight 30), 1 rare (weight 10). Each has an id, a name, a one-line description and a rarity. Keep the prototype's 8 names (Mossy, Odo, Bram, Tuck, Wren, Fen, Juno, Sol) and add 4.
- `WORLD-3` A world's residents appear only in that world's puzzles (daily or Explore).
- `WORLD-4` Finding all 4 residents of a world marks that world "complete" with a badge.

## 6. Game modes

### 6.1 Daily

- `DAILY-1` Date key = the device's local date, `YYYY-MM-DD`. Seed = `daily-<dateKey>`.
- `DAILY-2` Puzzle number = days from `LAUNCH_DATE` (config, default `2026-12-01`) to the date key, plus 1. Before launch date, show "Preview" instead of a number.
- `DAILY-3` Difficulty by weekday: Mon 1, Tue 2, Wed 2, Thu 3, Fri 3, Sat 4, Sun 5 (config).
- `DAILY-4` World by date: rotate through all worlds in order by puzzle number, regardless of what the player has unlocked. Everyone gets the same puzzle.
- `DAILY-5` The daily puzzle is always free and reachable in one tap from the home screen. First-time visitors land in the daily puzzle after onboarding with no sign-up.
- `DAILY-6` Progress saves continuously. Reloading resumes the puzzle with found items, misses, hints and elapsed time intact. The timer pauses while the page is hidden.
- `DAILY-7` If the date changes mid-puzzle, the player may finish; it counts for the date it was started.
- `DAILY-8` After completion the home screen shows the result and a countdown to the next puzzle.

### 6.2 Archive

- `ARCH-1` The last 7 daily puzzles before today are playable for free. Completing one is recorded as "late" and does not change the streak.
- `ARCH-2` Older dates are listed as locked. Tapping one opens the Premium screen with `source: archive`.

### 6.3 Explore

- `EXP-1` Each world has a ladder of 30 levels. Seed = `explore-<worldId>-<n>`. Difficulty rises along the ladder: levels 1–4 → 1, 5–10 → 2, 11–18 → 3, 19–25 → 4, 26–30 → 5.
- `EXP-2` Levels unlock in order. Worlds unlock per section 5. Locked worlds show their requirement and progress.
- `EXP-3` Explore does not affect the streak. Stars per level are saved and shown.

### 6.4 Play rules (all modes)

- `PLAY-1` Pan with one finger or mouse drag; pinch, wheel, double-tap and on-screen + / − buttons to zoom. Zoom range: whole world visible to 3× (config). Movement is clamped so the world never leaves the screen.
- `PLAY-2` A tap is a pointer down and up within 8 px and 300 ms. Drags never count as taps.
- `PLAY-3` Tap resolution uses `findNear` with a forgiving radius that scales with zoom (larger when zoomed out). A tap on an unfound target or the resident finds it. Anything else is a miss.
- `PLAY-4` Found: the object is marked in the world, its tray chip checks off, a short sound and haptic play. Miss: a small mark fades at the tap point and the miss counter rises.
- `PLAY-5` Three misses inside 2 seconds lock tapping for 3 seconds with a visible notice. (Stops tap-spamming.)
- `PLAY-6` Tray: bottom in portrait, side in landscape and desktop. Each chip shows the object drawn by the pack in its colour, with the name on long-press or hover. A separate slot shows "Someone is hiding here" until the resident is found.
- `PLAY-7` Hints: 1 free per puzzle (config). A hint moves the camera and shows a pulsing ring about 12% of world width that contains, but is not centred on, one unfound target, for 4 seconds. Further hints ask `ads.isRewardedAvailable()`; the default adapter says no, and the button then reads "1 free hint per puzzle" with a link to the Premium screen (`source: hints`).
- `PLAY-8` Stars: 1 for finishing, 2 for finishing with no hints, 3 for no hints and at most 2 misses. Time never affects stars.
- `PLAY-9` Finishing shows a result sheet: stars, time, misses, hints, resident found or not, streak, share buttons, and what to do next.
- `PLAY-10` Finding a resident shows a card with its name, rarity and whether it is new to the collection.
- `PLAY-11` Relaxed mode (setting): hides the timer and miss counter during play and removes the lockout in `PLAY-5`. Results still record them.

## 7. Progress and collection

- `META-1` Streak: completing today's daily on its own date extends the streak if yesterday was completed, otherwise sets it to 1. On open, a streak whose last completion is older than yesterday displays as 0. Track current and best.
- `META-2` Stats screen: played, completed, current and best streak, best and average time, three-star count, residents found.
- `META-3` Collection screen: residents grid grouped by world; unfound ones are silhouettes with rarity shown; found ones show name, description, times found and first-found date.
- `META-4` Worlds screen: the three worlds with unlock state, Explore progress and completion badge.
- `META-5` Storage: one versioned JSON document in `localStorage` (`hw:v1`), validated with Zod on load, with a migration function per schema version. If it fails validation, copy the raw value to a backup key and start fresh without crashing. All access goes through `src/state/storage.ts` with try/catch and an in-memory fallback when storage is unavailable.
- `META-6` Daily history is pruned to the most recent 60 days.
- `META-7` Settings has "Reset all progress" behind a confirmation.

## 8. Sharing

- `SHARE-1` Share text, spoiler-free, for example: `Hidden Worlds No. 12 · Harbour` / `9 of 9 found · 2:41 · no hints · ★★★` / `Streak 5` / link. Built by a pure function with unit tests.
- `SHARE-2` Share image: a 1080 × 1350 card drawn on a canvas with the app name, puzzle number, world, stars and stats over a blurred, cropped view of the world that reveals no target. Offered through the Web Share API with a file when supported, otherwise as a download.
- `SHARE-3` Share uses the Web Share API when available, otherwise copies to the clipboard (inside the click handler) and confirms on screen. Never use `alert`.
- `SHARE-4` Challenge link: the result sheet offers "Challenge a friend". The link carries the puzzle date and the sender's time, misses and hints in a compact, validated query parameter. Opening it starts that day's puzzle (if it is today or inside the free archive) with a banner "Beat 2:41", and the result sheet compares the two. Malformed or out-of-range links are ignored silently.
- `SHARE-5` Static Open Graph and Twitter card tags and one static share image, so links preview well.

## 9. Shell

- `SHELL-1` Screens: Home, Play, Result, Archive, Explore (worlds and levels), Collection, Stats, Settings, Premium, About. Routing by a small hash router or state; no router dependency needed.
- `SHELL-2` Onboarding on first run: three coach marks over the first puzzle (move and zoom, tap what is in the tray, someone is hiding). Skippable. Never shown again.
- `SHELL-3` Settings: sound, haptics, relaxed mode, colour-blind mode, reduced motion (follows the system by default), reset progress.
- `SHELL-4` Colour-blind mode: switches the eight object colours to a palette that stays distinguishable by lightness under simulated deuteranopia and protanopia (unit test on the simulated colours), and writes the colour name on each tray chip. It changes drawing only, never placement.
- `SHELL-5` Sound: short synthesised Web Audio sounds for found, miss, resident and finish. No audio files. Muted until the first user gesture and whenever the setting is off.
- `SHELL-6` Accessibility: every control is a real button with a label, reachable by keyboard, with a visible focus ring; touch targets at least 44 × 44 px; text contrast at least 4.5:1; honours `prefers-reduced-motion`.
- `SHELL-7` About screen: what the game is, a placeholder paragraph disclosing how the art is made (text in `strings.ts`, marked for the owner to edit), privacy summary ("no account, progress stays on this device, anonymous usage statistics only if enabled"), version and engine version.
- `SHELL-8` PWA: manifest generated from config, icons, offline play after first load, an in-app prompt when a new version is ready. An "Add to Home Screen" nudge appears once, after the second completed puzzle.
- `SHELL-9` Native-ready: no hover-only controls, safe-area insets respected, nothing essential depends on the service worker, no `window.open` for core flows.
- `SHELL-10` Resilience: a top-level error boundary with a "Reload" button; a visible loading state within 100 ms of start; the game still loads and plays if every font and every third-party request is blocked or stalls forever. (The prototype failed to load once because of a stalled, render-blocking font stylesheet.)
- `SHELL-11` Layout works from 320 × 568 to desktop. No horizontal scrolling. The world canvas backing store is capped (device pixel ratio at most 2) and big canvases are released when leaving Play, because iOS limits canvas memory.

### Visual direction

The owner cares about design. Aim for a naturalist's field guide, not a generic app.

- Palette (starting tokens from the prototype): ink `#13231d`, spruce `#1b3a30`, paper `#f1f5ea`, card `#ffffff`, line `#cdd8c6`, muted `#586c61`, gold `#ffb81c`, flare `#e5532d`.
- Type: Bricolage Grotesque, condensed and heavy, uppercase for titles and numbers; Figtree for everything else; tabular numerals for time and counts.
- Motifs: tray chips styled as specimen tags; residents presented as field-guide entries; thin ink rules; generous spacing; restrained motion (short, eased, never bouncy).
- Avoid: gradients-on-everything, glassmorphism, emoji as icons, purple, default system look. Draw the few icons needed as inline SVG.
- Use the `prototype/src/style.css` look as the starting point and raise it.

## 11. Adapters

Each adapter is an interface, a no-op default, and a factory that picks the implementation from environment variables. Nothing outside `src/adapters` knows which one is active.

- `ADPT-1` **Analytics**: `track(event, props)`, `identify(deviceId)`, `flush()`. Implementations: `noop` (default in production), `console` (default in dev), `memory` (tests), `posthog` (when `VITE_POSTHOG_KEY` is set; loaded lazily after first interaction; read PostHog's current docs and configure it for anonymous use with autocapture and session recording off).
- `ADPT-2` Events and properties, exactly these names:

| Event | Properties |
| --- | --- |
| `app_open` | `first`, `days_since_first`, `standalone`, `version` |
| `puzzle_start` | `mode`, `puzzle_no` or `level`, `world`, `difficulty`, `resumed` |
| `target_found` | `index`, `elapsed_s` |
| `hint_used` | `n`, `kind` |
| `resident_found` | `resident`, `rarity`, `new` |
| `puzzle_complete` | `mode`, `puzzle_no` or `level`, `world`, `difficulty`, `time_s`, `misses`, `hints`, `stars`, `resident_found` |
| `share` | `kind` (`text`, `image`, `challenge`), `method` |
| `challenge_open` | `puzzle_no`, `valid` |
| `world_unlock` | `world` |
| `premium_view` | `source` |
| `premium_interest` | `source`, `email_given` |
| `install_prompt` | `outcome` |
| `settings_change` | `key`, `value` |
| `error` | `message` |

- `ADPT-3` Every event carries `device_id` (random UUID created on first open), `app_version`, `engine_version`, `pack_id`. No personal data. Email, if given, goes only to the waitlist endpoint, never to analytics.
- `ADPT-4` **Ads**: `isRewardedAvailable()`, `showRewarded() → { rewarded: boolean }`. Default: unavailable.
- `ADPT-5` **Sync**: `pull()`, `push(state)`. Default: no-op. Storage calls it on save so a backend can be added later.
- `ADPT-6` **Waitlist**: `submit(email, source)`. Default: disabled.
- `ADPT-7` `.env.example` documents every variable. With no `.env`, the app makes no network request to any other origin (E2E test asserts this).

## 12. Content tools

- `TOOL-1` `npm run pack:build`: with no argument, builds the masks and logic data for the vector pack; with a folder path, builds `masks.bin` and fills in the mask entries for a PNG pack.
- `TOOL-2` `npm run pack:export-sample`: see `PACK-4`.
- `TOOL-3` `npm run pack:validate <dir>`: see `PACK-5`.
- `TOOL-4` `npm run world:audit -- --pack <id> --days 60`: generates the next N daily puzzles and all Explore levels; reports invariant failures, visibility by difficulty, generation time, how often each sprite type is a target, repeats of the same target on consecutive days, and resident distribution; writes contact-sheet PNGs to `out/audit/`. ## 13. Tests and the definition of done

### Unit (Vitest)

Engine acceptance (`ENG-A*`), pack validation, date and puzzle number (including month ends, leap day, daylight-saving changes), weekday difficulty, world rotation, streak rules, star rules, storage validation, migration and corruption recovery, share text, challenge encode/decode and rejection of bad input, colour-blind palette check.

### End-to-end (Playwright)

Projects: desktop Chromium, desktop Firefox, desktop WebKit, a phone-sized Chromium, a phone-sized WebKit. A test-only hook (enabled by a build flag, absent from the production bundle) exposes target positions so tests tap real screen pixels. Tests control the clock.

- `E2E-1` First run: onboarding, then a full daily play-through by real taps to the result sheet.
- `E2E-2` A tap on empty sky is a miss; a drag is not a tap; three fast misses trigger the lockout; relaxed mode removes it.
- `E2E-3` Hint works once, then the button changes and links to Premium.
- `E2E-4` Reload mid-puzzle resumes with state intact.
- `E2E-5` Complete today, advance the clock a day, complete again: streak is 2. Skip a day: streak resets.
- `E2E-6` Archive: yesterday is playable, a date 10 days back is locked and opens Premium.
- `E2E-7` Explore: level 2 locked until level 1 is done; Harbour locked until 3 residents are in the collection (seed storage).
- `E2E-8` Share falls back to clipboard and confirms; a challenge link opens with the banner; a malformed one is ignored.
- `E2E-9` Premium interest is recorded once and the screen says nothing was charged.
- `E2E-10` Offline: after one online load, go offline, reload, and play a puzzle.
- `E2E-11` Corrupt `hw:v1` in storage: the app starts fresh and keeps a backup.
- `E2E-12` With all font requests and all cross-origin requests aborted or stalled, the app still becomes playable.
- `E2E-13` No cross-origin requests with default config. No console errors in any test.
- `E2E-14` 320 × 568 and 360 × 640: no horizontal overflow on any screen; tray and controls reachable.
- `E2E-15` Golden engine check passes inside each browser (`ENG-A3`).
- `E2E-16` Time from navigation to a playable puzzle with 4× CPU throttling (Chromium): report it; fail above 5 s.

### Budgets

- `BUD-1` Initial JavaScript ≤ 250 KB gzipped. Total precached assets with the vector pack ≤ 3 MB. A script checks both.

### `npm run verify`

Runs, in order: typecheck, lint, unit tests, production build, budget check, pack validation, world audit (30 days), end-to-end tests. Exit code 0 only if all pass.

### Done means
